Tested end to end: a source with `pic0.dds` only builds a package whose CNT contains `pic0.png` (and the SDK-generated `license.dat`).

- **New default build method: the Sony SDK** (the `sdk-fpkg729-fix` toolchain, profile `sdk279-plaintext-unsigned-v2`). Packages are built by Sony's own Publishing Tools 2.79 command line (`prospero-pub-cmd.exe`, patched to leave the outer PFS plaintext and accept a custom keystone), in the same three steps as the toolchain's `build-from-folder.ps1`:
  1. **GP5 project.** The app writes a flat `<package name>.gp5` that lists every file explicitly, plus a default `<package name>.playgo-scenario.json`, next to the package — **byte-identical to what `create-gp5-from-folder.py --keep-keystone --absolute-paths` produces** for the same folder (verified against the bundled script in the test suite): same XML layout, same `Path.resolve()` paths, same exclusions and, most importantly, the same file order — Python's `str.casefold()` order, reproduced with the CPython folding table (`PythonCaseFold`), because Publishing Tools lays the image out in GP5 order and a different order is a different package. Files the SDK regenerates are left out: PlayGo tables, `pfs-version.dat`, `imagedigs.dat`, `param.sfo`, `sce_sys/about/`, `.dds`/`.auth_info`, old `.gp4`/`.gp5` projects and `ampr_emu.index`. The source's 96‑byte `sce_sys/keystone` is always kept. Symbolic links are rejected like the script does. The GP5 points straight at the source files, so **no mirror folder and no links are needed** (the junction error on exFAT drives cannot happen); the only file the app substitutes is the patched `sce_sys/param.json`, written to the temporary folder.
  2. **Raw package.** `img_create --oformat nwonly` compresses at Sony's default level (7), generates PlayGo and writes the package directly into the output folder.
  3. **Conversion.** The raw package becomes a LibProsperoPkg-compatible `PLAINTEXT_NOAUTH` package: `PPRPLAIN-NOAUTH!` marker, CNT encryption flags cleared, image digests, FIH/CNT cross-references, entry digests and rollups resealed, the deterministic RSA‑3072 CNT header wrap rebuilt, and the PlayGo CRC32C table in the SI archive repaired.

  The conversion is a C# port of `postprocess-sdk279-plaintext.py` that produces **byte-identical** output. It patches the package in place instead of copying it, and nothing needs Python. Like `build-from-folder.ps1`, the `.gp5`, the `.playgo-scenario.json` and a `<package name>-build-logs` folder (`01-create-gp5.log`, `02-img-create.log`, `03-postprocess.log`, same keys as the script) stay next to the package; the raw `.sdk-plaintext.pkg` and `.naps_metric.json` are removed.

  End-to-end check against the original toolkit (Python scripts + Wine) on the same 400 MB test game: identical file list, every extracted file byte-identical, and the packages differ only in the ~2 KB that depend on the build timestamp (`pubtools.creationDate`, digests, CRCs) — the same difference as running the toolkit twice.

## 2.1.9 — 2026-09-16

- **LibProsperoPkg engine from fpkg-gui 0.6.8.** Same public API (1.2.0) plus a new PlayGo builder, package verification and DRM options.
- **PlayGo is always regenerated by the engine.** The new engine never copies the dump's `playgo-chunk.dat` / `playgo-hash-table.dat` / `playgo-ficm.dat` / `playgo-scenario.json` into the package: every table, the scenario file and the scenario images are rebuilt for the new image ("Fixed an issue with PlayGo map creation"). When the files are kept it only reads the chunk and scenario counts from `playgo-chunk.dat` (or `scenarioCount` from `playgo-scenario.json`). The chunk range grows from 1–64 to **1–255** and the fallback default from 64 to **100**; settings still holding the old default of 64 move to 100 once.
- **Broken PlayGo inputs no longer stop the build.** The engine aborts with "Invalid PS5 playgo-chunk.dat header." when a kept file is malformed. With "Drop old playgo*" off, the tool now checks both files with the engine's own rules (magic `plgx`, version `0x1000`, stored length, 1–255 chunks, 1–64 scenarios) and leaves only the broken ones out, with a warning. The source card shows the counts the engine will use.
- **DRM "standard" is applied by the engine** (`ForceStandardApplicationDrm`) in memory instead of through a patched `param.json`, so forcing DRM alone no longer needs a mirror or overlay. The log still names the original value.
- **`requiredSystemSoftwareVersion` is lowered to the game's SDK** ("Automatic downgrading of the required software version to the SDK-specified version"). When you pick an SDK the engine sets both `sdkVersion` and `requiredSystemSoftwareVersion` to it. When you keep the game's SDK, a new toggle (on by default, CLI `--keep-required-fw` to opt out) lowers `requiredSystemSoftwareVersion` to the major/minor of `sdkVersion` whenever it is higher, e.g. 10.40 → 4.50. It never raises the value, and the source file is not touched.
- **Every build is verified by the engine.** After the structural check, the new quick verification reads the package metadata: segment ranges, CNT signature and entry digests, the complete PlayGo layout, the outer PFS superblock, NAPS, inner PFS inodes and the SI directory. It takes milliseconds to seconds. A package that fails is reported as a failed build instead of a success. New option **Full check after building** (off by default, CLI `--full-verify`) also decrypts every outer block, matches it against `imagedigs.dat` and test-decompresses every file in memory.
- **Quick check / Full check buttons in Extract PKG mode** for any existing package, with progress and cancel. `fpkg-cli verify` runs the same checks (`--full`, `--passcode`) and exits with code 2 when a package fails.
- **Export DLC template** (fpkg-gui 0.6.8). Opening a DLC package with data in Extract PKG mode shows an **Export DLC template** button. It writes the `sce_sys` files needed to rebuild the DLC (`param.json`, `license.dat` / `license.info`, PlayGo, icon) plus a `<Content ID>.gp5` project to a `<package>-dlc-template` folder next to the `.pkg`. The project carries the DLC volume type, Content ID, passcode, the entitlement key read from `license.info`, and the original chunk/scenario layout. The payload is not copied: put the DLC data in the folder and pick the `.gp5` as the source to build the package again. CLI: `fpkg-cli pkg-dlc-template <file.pkg> [--output <dir>]`.
- **Temporary folder on a different drive from the source or output.** Reported on Discord: picking the temporary folder on one drive and the output on another failed with "files cannot be dropped". The mirror folder is built from links, and a directory junction can only live on NTFS, so on Windows a temporary folder on an exFAT/FAT32 external drive (or a network drive) could not hold it and every build stopped. Now:
  - The mirror is only a few links plus `sce_sys`. When the chosen temporary folder cannot hold links, it is built in the system temporary folder instead; the large temporary data still goes to the folder you chose.
  - Junctions are created directly through the Windows API (`FSCTL_SET_REPARSE_POINT`); `mklink /J` remains only as a fallback.
  - Extracted images (`.exfat` extraction, `.ffpfsc`, `.ffpkg`) are the tool's own copy, so files are dropped and `param.json` patched in place, with no links at all.
  - A temporary folder you chose yourself is no longer reset at startup when it sits on a different drive from the output folder.
  - The log names both drives and their file systems, and warns when the temporary or output folder is on FAT/FAT32, which cannot hold the 4 GB+ files a game package needs. The disk-space line in the app shows the same warning.
- **macOS: no more `._*` files inside packages built through an exFAT/FAT drive.** macOS 26 tags every newly created file with `com.apple.provenance`, and exFAT/FAT store that as an AppleDouble `._name` file next to it. A temporary folder on such a drive therefore produced packages containing `sce_sys/._param.json` and a `._` twin for every extracted file. Those AppleDouble files (magic `0x00051607`) are now removed from the mirror and from extracted copies before packaging. Links are never followed, and files that exist in your source are never touched.
- **macOS: temporary folders on exFAT/FAT drives are removed again.** The new FSKit exFAT/FAT driver lists accented names in NFD form but silently ignores a delete by that same name, so an extraction folder containing Vietnamese file names stayed behind ("Directory not empty"). Deletion now retries with the other Unicode normalization form.
- Tests: 220, including real builds that confirm DRM, required-version lowering, SDK override, PlayGo count import, broken-input skipping, quick and full verification (app, homebrew and Native-image packages), and that a single flipped byte fails the full check.

## 2.1.8 — 2026-09-14

- **New source format: `.ffpkg`.** These dumps are a **FreeBSD UFS2 filesystem image** — superblock at byte 65536, magic `0x19540119` at offset 1372, 64 KiB blocks — whose root directory *is* the game's app folder. macOS dropped UFS in 10.7 and Windows never had it, so neither system can mount one; the tool now parses the format itself: superblock, cylinder groups, 256-byte inodes with 12 direct block pointers and three levels of indirection, then the directory records. Pick one with the new **.ffpkg file** button, drag and drop it, or pass it to `fpkg-cli inspect` / `build --source x.ffpkg`. Metadata, icon, statistics, junk-file listing, validation and packaging all behave exactly as they do for `.exfat`; because no OS can mount UFS the image is extracted to the temporary folder using that reader. Verified end to end on a real 3.6 GB dump: 17,407 files and 2,343,308,017 bytes, matching an independent reader written separately to check the numbers.
- **macOS no longer extracts `.exfat` images.** An `hdiutil` mount is read-only, so until now anything that needed files dropped (`playgo*`, OS junk) or `param.json` patched forced a full extraction to the temporary folder. The mirror folder can now be built directly on top of the mounted volume — it only *reads* from the mount and writes changes into the temporary folder — so the image is mounted and read in place, with no copy. OS junk is skipped in the mirror too and gets its own log line.
- The mirror no longer uses `File.Copy`: on macOS that copies extended attributes and throws "Attribute not found" when the source sits on a freshly mounted exFAT volume. It now copies file contents only.
- When the mirror cannot be built the log names the exact file that failed instead of showing a bare error.
- The five source buttons wrap onto a second line when the window is narrow, so their labels are no longer cut off.
- The build log no longer calls every image an "exFAT image".
- Tests: 198.

## 2.1.7 — 2026-09-14

- **"Application error" the moment the game starts ("playgo" error in the PS5 log) — fixed at packaging time, for every source type.** An FPKG is one single unified image while PlayGo is built around chunk-based installs, so the dump's PlayGo data makes the console look for chunks that do not exist. Per Drakmor, dropping those files clears the application error at launch; a game that hangs on the splash screen without an error (Stellar Blade, Ghost of Yōtei) has a different, kernel-side problem that packaging cannot fix. The build now applies the known fix by default: the `sce_sys/playgo*` files (`playgo-chunk.dat`, `playgo-hash-table.dat`, `playgo-ficm.dat`, `playgo-scenario.json`) are left out and the library generates a fresh PlayGo set matching the image; `versionFileUri` in `param.json` is cleared; and `attribute3` is set to 0. Three toggles in the advanced options ("PlayGo fix" box), plus CLI `--keep-playgo`, `--keep-version-uri`, `--keep-attribute3` to opt out of any of them. Note on `attribute3`: no public documentation maps a PlayGo bit in that field, so the whole field is set to 0 exactly like unchecking every flag in a PARAM editor — the documented flags (video-out info, Share Library Capture API, HFR, High Framerate Mode, Auto Scaling) are switched off in the package too.
- Works for **app folders, `.exfat` and `.ffpfsc` images and GP5 projects**. Folders and extracted images have the files moved aside during the build; a Dokan virtual drive hides them and overlays the patched `param.json` without touching the image; a read-only `hdiutil` mount now extracts instead, because it cannot hide anything; GP5 projects have the `.gp5` file rewritten temporarily (exclude masks for the Normal layout, the explicit `<file>` entries dropped for the Flat layout). Every source file, and the `.gp5` itself, is restored byte-for-byte afterwards — also when the build fails or is cancelled.
- `fakelib/libScePlayGo.sprx` is **never touched by this tool**. Verified on a real package: the LibProsperoPkg engine drops that module (and `fakelib/libSceAmpr.sprx`) from `fakelib` by itself, while every other module — and the copies in `fakelib2` — are packaged normally. No option here changes that.
- **`fakelib/libScePlayGo.sprx` and `fakelib/libSceAmpr.sprx` are removed by the LibProsperoPkg engine itself**, with no option to turn that off — verified by disassembling `ProsperoPkgBuilder.BuildInnerTree`, which finds the first directory named `fakelib` and calls `Files.RemoveAll(f => f.name == "libSceAmpr.sprx" || f.name == "libScePlayGo.sprx")`. Fourteen ways of feeding those files in (plain folder, GP5 Flat explicit entry, renamed source directory, letter-case variants, duplicated `fakelib` entries, `<dir>` plus `<file>` shapes) were all removed; only other paths survive (`sce_module/`, `fakelib2/`, `fakelib/<subdir>/`). This tool never touches those files — the removal is the engine's own behaviour.
- **AMPR emu index.** The engine strips `fakelib/libSceAmpr.sprx` (needed for backport and dlc_emu, per its author) but kept `ampr_emu.index` ("I forgot about the index"). The app now removes that leftover as well — advanced toggle "Clean up AMPR emu leftovers" (on), CLI `--keep-ampr`; `fpkg-cli inspect` prints an `AMPR:` line.
- **DLC packages from `dlc_emu.ini`.** Drakmor's DLC emulator (`dlc_emu.ini` + `libSceAppContent` / `libSceNpEntitlementAccess` / `libSceGameUpdate` in `fakelib`) is **kept in the package** — it is not what caused the black screen. When a source carries one, the source card offers to build a real DLC package for every entry in that game's `dlc_emu.ini` (about 0.7 MB each, each with its own RIF `license.dat` / `license.info`; built as *additional content with data* over an empty data folder because the entitlement-only form is a bare CNT the PS5 debug installer refuses), so the DLC also unlocks through the normal path. CLI: `fpkg-cli dlc-from-ini <folder|image|dlc_emu.ini> --output <dir>`; `inspect` lists the entries. An advanced toggle (`--strip-dlc-emu`) removes the emulator from the package instead, dropping a `fakelib` left empty by the cleanup. Extracted entitlement-only DLC packages are labelled "DLC — entitlement only, no data (installable)" instead of "metadata only".
- **Build panel checkboxes.** "DRM standard" and "Drop old playgo*" sit right next to the Build button; both are saved with the rest of the settings. New **Restore defaults** link puts every packaging option back to its default value after a confirmation — paths, package info read from the source, language, theme, history and window size are kept.
- **Same-named package in the output folder now asks first**: overwrite, keep the old one (renamed to `… (1).pkg`, numbered upwards) or cancel — in the app, and in `fpkg-cli` via a console prompt or `--overwrite` / `--keep-existing`. Previously the old package was silently replaced.
- Tests: 191, including a full snapshot of the source tree (paths, sizes, SHA-256, timestamps) asserted identical after successful, cancelled, failed and GP5 builds.

## 2.1.0 — 2026-09-13

Updated to the latest **LibProsperoPkg** (from `fpkg-gui 0.6.2`) and exposed its new capabilities.

### Library (LibProsperoPkg)
- Faster large-package builds through overlapping reads, compression and writes, with fewer intermediate copies.
- Block deduplication and an in-build compression cache.
- Improved built-in Kraken compression, especially at levels 8–9.
- PFS v2 / v3 selection, configurable compression block size and automatic shuffle selection for PFS v3.
- Automatic fallback to the built-in Kraken encoder when Oodle Reduced is unavailable.
- Improved progress reporting (byte throughput), reduced log verbosity.
- File-handling and build-cancellation fixes; existing packages are preserved if a rebuild fails.

### Measured on a 21.3 GB real game (macOS, Apple Silicon, built-in Kraken)
| Library | Time | Package |
|---|---|---|
| LibProsperoPkg shipped with 2.0.0, "Kraken 7" (= Normal encoder) | 3 min 40 s | 9.03 GiB |
| LibProsperoPkg shipped with 2.1.0, **Standard (Kraken 4, default)** | **2 min 13 s** | **8.86 GiB** (−1.9 %) |
| LibProsperoPkg shipped with 2.1.0, Smallest (Kraken 7 Optimal) | 12 min 49 s | 8.54 GiB (−5.5 %) |

Side by side on the same 400 MB set the 2.0.0 engine produced identical packages at levels 4 and 7 (its "level 7" was the Normal encoder) and the 2.1.0 engine at level 4 reproduces that result at the same speed, so **Standard** keeps the old size and speed while **Smallest** is a genuinely new, slower Optimal mode.

### App / CLI
- New advanced options: **PFS compression format (v2 / v3)**, **Kraken block size (128–256 KiB)**, **pre-compression shuffle pattern**, **automatic shuffle analysis**, **skip PFS input check** (expert), **physical layout optimisation**.
- **Presets re-mapped to the new encoder.** The 2.0.0 engine used the same Normal encoder for levels 4–7 (identical output at level 4 and 7); in 2.1.0 level 4 reproduces that result at the same speed while level 7 is a new, ~5–6× slower *Optimal* mode. The default preset is therefore **Standard = Kraken 4** (the old "Kraken 7" size and speed, plus dedup/layout gains; CLI id `balanced`, aliases `sony` / `standard`); **Smallest = Kraken 7 Optimal** (~3 % smaller, 5–6× slower) stays available.
- New **Maximum** preset (Kraken 9 + PFS v3 + shuffle analysis) next to Fast / Standard / Smallest. Per the library author: the PFS v3 shuffle mechanism optimises texture compression, is very time-consuming and only fully effective at level 9, and PFS v3 packages need PS5 firmware 7.00 or newer — the app shows these warnings in the advanced options and the build log.
- Build panel shows the live **throughput** (MiB/s) next to the ETA; progress model covers the new planning and layout phases.
- Smoother progress on large games: the inner-compression phase is now estimated from the library’s per-file lines (byte-weighted), so the bar moves every few seconds instead of once per multi-GB file; phase weights re-tuned from a 21 GB real-game build.
- New `PSVIETHOA_SCROLL=<pixels>` dev hook for documentation screenshots.
- CLI: `--pfs`, `--block-size`, `--shuffle`, `--shuffle-analysis`, `--shuffle-prediction-level`, `--skip-pfs-input-check`, `--no-layout-optimization`, `--source-mode`, `--project` (GP5).
- New **Extract PKG** mode (Build | Extract mode bar under the header): inspect a `.pkg` (FIH / CNT headers, region map, every `param.json` field, icon, sce_sys entries) and list the files of the inner PPR-PFS image; filter, tick files/folders and extract a selection or the whole package with progress and cancel; export `sce_sys` / SI entries; optional SHA-256. PLAINTEXT_NOAUTH packages are decoded in place in 4 MiB chunks (LRU cache, no temp image); Native (AES-XTS) packages are decrypted to the temp folder first; retail packages are information-only. CLI: `pkg-info`, `pkg-list`, `pkg-extract` (`--include` globs, `--cnt`, `--threads`). Dev hooks `PSVIETHOA_MODE=extract`, `PSVIETHOA_EXTRACT_PKG=<pkg>`, `PSVIETHOA_EXTRACT_PREVIEW=<path or file name inside the package>`, `PSVIETHOA_AUTOEXTRACT=1`.
- **GP5 project as a third source type** (`.gp5`, mirroring fpkg-gui's Folder | GP5 selector): ".gp5 project" button in step 1 and drag & drop; metadata, size and validation are read through the project (Normal or Flat layout, `global_exclude` / `dir_exclude` / `file_exclude` masks, relative paths resolved from the `.gp5` folder); the project's passcode pre-fills the passcode field; new advanced **Source reading mode** (automatic top-level `.gp5` / folder only) for folder sources; `fpkg-cli inspect` and `build --source x.gp5`.
- New PSVIETHOA logo (`docs/logo.svg`): app icon on macOS / Windows, window header and README banner are generated from it (`scripts/make-icons.py`, `scripts/make-banner.py`).
- Credits shown in the header, footer, help window and CLI.
